Cloud sync

A sync client copies a delete to the cloud within seconds, so the real undo is the provider's version history and deleted-files bin. undomap only counts it when it can show the history covers the path. The probe is read-only and can't fail the map.

The demotion rule. A path moves to Zone AE (kind: "cloud") only when all of these hold:

  1. the client's own config (Dropbox info.json, the OneDrive environment variables, the ~/Library/CloudStorage folder the client creates) points at a folder containing it;
  2. the client is running right now (ps / tasklist), so the folder isn't a stale copy;
  3. no known gap applies to the path or any folder above it, and its largest file is under the provider's per-file limit;
  4. for Dropbox, the ignore attribute could be read and isn't set, and rules.dropboxignore doesn't match.

iCloud Drive never demotes: it keeps deletes but not overwrites, and an agent overwriting a file is as final as deleting it. Anything undomap can't confirm (client not running, a folder name or .dropbox marker with no client config, attributes it can't read) stays in Zone VE with possible cloud versioning, unverified in the reason, the probe line, and one cloud sync line under the report with the cheapest way to check. A snapshot or backedUp still wins over all of this.

What it can't see. A paused sync, a full quota, or a subfolder inside a place that's marked ignored (undomap checks the place itself and the folders above it). If the client shows errors, treat cloud Zone AE as Zone VE. iCloud's Desktop & Documents sync isn't detected, which only errs towards Zone VE.

                    { "path": "GITHUB_TOKEN", "type": "token-like name", "where": "env" }],
    "credentialsCapped": false,
    "network": { "status": "open", "detail": "eth0 has an address (no connection attempted)" },
    "writable": [{ "path": "/home/me", "why": "your home folder" }],
    "legs": 3, "trifecta": true,
    "fix": { "say": "break one leg: …", "run": "env -u GITHUB_TOKEN "$SHELL"", "cost": "minutes" }
  }
}

cloud is present for a path inside a sync folder: status is covered (graded AE), unverified, partial (iCloud: deletes only) or gap (the provider skips it); note says why. forcedBy is present when a permanent pattern from .undomap.json matched the path (see precedence); why then says the config forced it. Paths are relative to root, use POSIX separators, and directories end in /. capped: true means sizing stopped at 250,000 entries for that place, so bytes is a lower bound (shown with a +). Remote URLs are never printed, only remote names, because URLs can carry tokens.

reach (only with --reach): where is tree (path relative to root), home (absolute) or env (the variable name: never its value). network.status is open, closed (loopback only, or the Codex sandbox's network-disabled flag) or unknown (loopback plus a proxy, as sandboxes with an allowlist set up). legs counts the three conditions; trifecta is all three.
